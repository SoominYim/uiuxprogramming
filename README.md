# 초록달력

처음 식물을 키우는 1인 가구 및 자취생을 위한 맞춤 물주기 알림 서비스입니다.

- **GitHub 저장소 주소**: https://github.com/SoominYim/uiuxprogramming
- **배포 주소**: https://soominyim.github.io/uiuxprogramming/

---

## UX 계획

- **사용자**: 처음 식물을 키우는 자취생
- **목적**: 식물 관리 방법과 물주기 시기를 이해한다.
- **핵심 행동**: 키우는 식물을 등록하고 물주기 알림을 신청한다.
- **정보 순서**: 서비스 소개 → 주요 기능 → 이용 방법 → 이용 설정 → 알림 목록 → 소식 받기

## 2주차에서 바꾼 구조와 이유

- `h1 + p`로만 되어 있던 1주차 본문을 `header` 안으로 옮겼습니다. 서비스 이름과 소개 문장이 페이지의 다른 정보(소개, 기능, 이용 방법 등)와 구분되는 대표 영역임을 나타내기 위해서입니다.
- 서비스 소개, 주요 기능, 이용 방법, 소식 받기를 각각 `section#about`, `section#features`, `section#steps`, `section#subscribe`로 묶고 이 네 영역을 `main`으로 감쌌습니다. 사용자가 실제로 이용하는 핵심 콘텐츠와 머리말(`header`)·꼬리말(`footer`)의 역할을 분리하기 위해서입니다.
- 주요 기능 3개는 순서를 바꿔도 의미가 유지되므로 `ul`로, 이용 방법 3단계는 순서대로 따라야 하므로 `ol`로 작성했습니다.
- `header`에 `nav`를 추가하고 각 링크의 `href`를 해당 `section`의 `id`와 연결해 페이지 안에서 바로 이동할 수 있게 했습니다.
- 소식 받기 영역은 `label for="email"`과 `input id="email"`을 연결해 라벨을 눌러도 입력칸이 선택되도록 했습니다.
- 서비스 이미지는 준비된 `assets/images/service.jpg`를 연결했습니다.

## AI 비교 기록

동일한 서비스 소개("초록달력")를 AI에게 그대로 생성시킨 결과와 직접 구현한 `index.html`을 비교했습니다.

**정보 계층**
- 직접 구현: `h1`(서비스 이름) 아래로 `h2`(서비스 소개/주요 기능/이용 방법/소식 받기)와 `h3`(각 섹션의 세부 주제)를 두어, 페이지 전체에서 제목 위계가 하나로 통일됩니다.
- AI 생성본: 기능 카드마다 `h2`를 반복하거나 강조 목적으로 `h1`을 여러 번 사용해, 페이지의 대표 제목이 무엇인지 문서 구조만으로는 알기 어려운 경우가 많았습니다.

**시맨틱 구조**
- 직접 구현: `header`·`nav`·`main`·`section#about/#features/#steps/#subscribe`·`footer`로 콘텐츠의 역할과 포함 관계를 태그 자체로 표현했습니다.
- AI 생성본: `<div class="header">`, `<div class="section">`처럼 의미는 클래스 이름에만 담고 실제 태그는 `div`를 반복 사용하는 경우가 있어, 브라우저나 스크린 리더가 문서의 역할 구조를 인식하지 못합니다.

**접근성**
- 직접 구현: `nav aria-label="주요 메뉴"`, `label for="email"` + `input id="email"` 연결, 이미지 의미를 설명하는 `alt` 텍스트를 갖췄습니다.
- AI 생성본: `input`에 `label` 없이 `placeholder`만 넣거나, `alt="image"`처럼 형식적인 대체 텍스트만 넣는 경우가 있어 스크린 리더 사용자가 입력 목적이나 이미지 의미를 파악하기 어렵습니다.

**배운 점**
AI가 생성한 코드는 화면상의 모양은 비슷해 보여도, 태그 선택과 속성 연결까지 신경 쓰지 않으면 접근성과 문서 구조에서 차이가 크게 벌어진다는 것을 확인했습니다. 이번 과제에서는 역할(태그)·순서(위계)·포함 관계(중첩)·행동(연결 속성)을 직접 설계했기 때문에 이 차이를 좁힐 수 있었습니다.

## 3주차 CSS 수정 기록

### 수정한 내용
기능 카드를 가로로 나란히 배치하기 위해 부모 요소인 `.feature-list`에 `display: flex`와 `gap: 20px`을 적용하고, 자식 요소인 `.feature-card`에 `flex: 1`과 패딩, 테두리, 배경색을 적용했습니다.

### 수정 이유
세 가지 핵심 기능(물주기 알림, 식물 도감, 성장 기록)이 동일한 위계의 정보 그룹임을 한눈에 비교할 수 있게 하고, 카드 간격과 크기를 균등하게 유지하여 정보 탐색 피로도를 낮추기 위해 수정했습니다.

| 바꾼 속성 | 화면 변화 | 사용자 이점 |
| --- | --- | --- |
| `display: flex` · `gap: 20px` | 세 기능 카드가 한 줄에 균등한 너비와 일정한 간격으로 배치됨 | 제공되는 핵심 기능을 한눈에 비교하고 탐색하기 쉬워짐 |
| `hover` · `focus` · `active` · `transition` | 버튼과 링크 조작 시 배경색 변경, 아웃라인 강조, 미세 이동 등 부드러운 피드백 제공 | 현재 조작 중인 요소와 입력 상태를 명확히 인지할 수 있음 |

## 5주차 JavaScript 수정 기록

### 구현한 기능
- 물주기 알림 및 소식 받기(`subscribe-form`) 폼에 실시간 사용자 피드백 기능을 구현했습니다.
- 이메일 입력 여부에 따라 동적 피드백 문구를 출력하고, 성공 시 완료 스타일과 버튼 비활성화 상태를 제공합니다.

### 사용한 개념 및 적용 내용
1. **DOM 선택**: `document.querySelector`로 폼, 입력창, 버튼, 안내 문구 요소를 선택했습니다.
2. **변수 관리**: 서비스명은 `const`, 신청 완료 상태는 `let` 변수로 관리했습니다.
3. **조건문과 일치 비교**: `===` 연산자를 활용하여 빈 입력값 예외 처리와 성공 처리를 분기했습니다.
4. **함수와 반환**: `makeFeedbackMessage(email, subscribed)` 함수로 상태에 맞는 안내 문구를 반환했습니다.
5. **이벤트 연결**: `addEventListener("submit", handleSubscribe)`를 연결해 폼 제출 시 인터랙션이 발생하도록 구현했습니다.
6. **상태 피드백**: `classList.add("is-saved")`와 `disabled = true`로 신청 완료 피드백을 제공하고 중복 제출을 방지했습니다.

## 6주차 이벤트와 동적 UI 수정 기록

### 1. 구현한 이벤트 및 화면 변화
- **`click` 이벤트 (화면 테마 전환)**:
  - `#themeButton` 클릭 시 `document.body.classList.toggle("dark")`를 실행하여 밝은 테마와 다크 테마를 전환합니다.
  - 테마 상태에 따라 버튼 문구가 `"어두운 테마로 바꾸기"` ↔ `"밝은 테마로 바꾸기"`로 실시간 변경됩니다.
- **`input` 이벤트 (실시간 글자 수 카운팅)**:
  - 반려식물 애칭/이름 입력창(`#userName`)에 글자를 입력하거나 삭제할 때마다 `input` 이벤트를 감지합니다.
  - `userNameInput.value.length`를 계산하여 `#userNameCount`에 `현재 글자 수 / 10` 형식으로 즉시 업데이트합니다.
- **`change` 이벤트 (체크박스 상태 및 다중 화면 피드백)**:
  - 이용 안내 확인 체크박스(`#agreeCheck`)의 `change` 이벤트를 감지합니다.
  - 체크 여부(`checked`)에 따라:
    1) 안내 문구(`#agreeMessage`) 내용 변경 (`textContent`)
    2) 안내 문구 스타일 클래스 토글 (`classList.toggle("is-ready", agreed)`)
    3) 시작하기 버튼(`#startButton`) 활성화/비활성화 제어 (`disabled = !agreed`)
    - 사용자 행동 한 번에 문구·스타일·버튼 상태 세 가지가 유기적으로 함께 변경됩니다.

### 2. 탭 UI 구현
- 기존의 '주요 기능' 영역을 `role="tablist"`와 `role="tabpanel"` 기반의 3개 탭으로 재구성했습니다.
  - 탭 1: 물주기 알림 (`#tab-watering` → `#panel-watering`)
  - 탭 2: 식물 도감 (`#tab-guide` → `#panel-guide`)
  - 탭 3: 성장 기록 (`#tab-record` → `#panel-record`)
- `querySelectorAll()`과 `forEach()`를 통해 모든 탭 버튼에 클릭 이벤트를 일괄 연결했습니다.
- `data-target` 속성과 `dataset.target`을 읽어와 클릭된 탭에 대응하는 특정 패널만 `hidden`을 해제하고 `.is-active` 클래스를 부여하며, 나머지 탭과 패널은 초기화하여 항상 하나의 패널만 노출되도록 구현했습니다.

## 7주차 사용자 흐름과 인터랙션 시나리오 설계

> 7주차 교안 지침에 따라 기존 4주차 반응형 단독 기록 위치를 본 서비스의 종합적인 사용자 흐름 및 인터랙션 시나리오로 통합·개편했습니다.

### 1. 사용자 흐름 (User Flow)
1. **진입**: 서비스 이용 설정 섹션에서 이용 안내를 확인(체크)하고 활성화된 '서비스 시작하기' 버튼을 누른다.
2. **입력**: 식물 이름(애칭)과 마지막으로 물 준 날짜를 입력한다. 필수값이 비어 있으면 다음 단계로 넘어가지 않고 오류 안내를 띄워 같은 단계에서 수정을 유도한다.
3. **선택**: 키우는 식물 종류(몬스테라, 다육이/선인장, 스킨답서스, 테이블야자)를 선택한다. 다육이나 선인장처럼 주의가 필요한 식물은 과습 방지 도움말이 나타난다.
4. **확인**: 앞서 입력한 식물 이름, 날짜, 식물 종류를 한눈에 검토한다. 수정이 필요하면 '이전' 버튼을 눌러 기존 입력값을 유지한 채 고칠 수 있다.
5. **완료 및 다시 시작**: 알림 신청 완료 안내를 확인한다. '다른 식물 등록하기' 버튼을 누르면 입력값과 상태를 초기화하고 1단계로 돌아가 새 식물을 등록할 수 있다.

### 2. 인터랙션 시나리오
| 행동 | 이벤트·조건 | 화면 반응과 다음 상태 |
| --- | --- | --- |
| 이용 안내 체크 및 서비스 시작 클릭 | `click` · 동의 체크 완료 상태 | 단계별 알림 신청 영역(`#plantFlow`)의 숨김을 해제하고 1단계(식물 정보 입력)를 표시하며, 식물 이름 입력창으로 부드럽게 스크롤 및 포커스 이동한다. |
| 이름 또는 날짜 없이 다음을 누름 | `click` · 필수 입력값 누락 | 비어 있는 항목에 맞춰 오류 메시지(`#plantError`)를 띄우고, 해당 입력창에 붉은 테두리(`.has-error`)를 주며 포커스를 이동해 같은 단계에 머문다. |
| 필수값 입력 후 '식물 종류 선택하기' 클릭 | `click` · 이름과 날짜 모두 입력됨 | 오류 메시지와 붉은 테두리를 지우고 2단계(식물 종류 선택) 화면을 표시한다. 진행 상태를 '2 / 3 · 식물 종류 선택'으로 갱신한다. |
| 식물 종류를 '다육이 / 선인장'으로 변경 | `change` · 선택값이 `succulent`인 경우 | 과습 예방 주의 도움말(`#plantHelp`)을 화면에 표시한다. 다른 식물 선택 시 도움말을 다시 숨긴다. |
| 2단계에서 '정보 수정하기' 클릭 | `click` · 이전 단계 요청 | 입력했던 이름과 날짜 값을 그대로 유지한 채 1단계 화면으로 돌아가고 이름 입력창에 포커스한다. |
| 2단계에서 '신청 내용 확인하기' 클릭 | `click` · 확인 단계 요청 | 입력한 이름, 날짜, 선택한 식물 종류를 요약 문구(`#plantSummary`)로 조합하여 표시하고 3단계 화면으로 전환한다. 진행 상태를 '3 / 3 · 신청 내용 확인'으로 갱신한다. |
| 3단계에서 '종류 수정하기' 클릭 | `click` · 이전 단계 요청 | 선택했던 식물 종류를 그대로 유지한 채 2단계 선택 화면으로 돌아간다. |
| 3단계에서 '알림 신청 완료하기' 클릭 | `click` · 완료 요청 | 4단계 완료 화면을 표시하고 완료 안내 문구를 노출한다. 진행 상태 텍스트를 '신청 완료'로 변경한다. |
| 4단계 완료 후 '다시 신청하기' 클릭 | `click` · 초기화 요청 | 입력값(이름, 날짜), 선택값(식물 종류), 오류 메시지, 요약 문구, 도움말 숨김 상태를 모두 초기화하고 1단계로 돌아가 이름 입력창에 포커스한다. |

### 3. 코드 구현 내용
기존 1~6주차의 마크업, 스타일, 이벤트를 훼손하지 않고 7주차 사용자 흐름을 자연스럽게 연결했습니다.
- **`index.html`**: 기존 이용 설정 뒤에 `#plantFlow` 섹션 및 1~4단계 추가, 레이블-인풋 연결 및 접근성 속성(`aria-live`, `aria-describedby`, `role="alert"`) 적용
- **`style.css`**: 단계 숨김(`[hidden]`), 진행도 뱃지, 오류 테두리(`.has-error`), 요약/도움말 박스, 768px 모바일 반응형 및 다크 테마 지원
- **`script.js`**: `startButton`과 연동, `showPlantStep()` 단계 전환, 필수값 검증, 동적 도움말, 값 유지 및 초기화(`plantRestart`) 로직 작성

### 4. 조작 테스트 결과
- **정상 경로**: 이용 안내 동의 → 서비스 시작하기 → 이름('초록이')과 날짜 선택 → 몬스테라 선택 → 내용 확인 → 완료 단계까지 순서대로 정상 이동함을 확인했습니다.
- **빈 입력(오류) 경로**: 이름을 입력하지 않고 다음을 누르면 오류 메시지가 뜨고 테두리가 붉은색으로 바뀌며 해당 창으로 포커스가 이동했습니다.
- **이전 단계 및 값 유지**: 2단계에서 '정보 수정하기'나 3단계에서 '종류 수정하기'를 눌렀을 때 기존 입력값이 지워지지 않고 유지되며, 수정 후 다음 단계에 정상 반영됨을 확인했습니다.
- **다시 시작(초기화)**: 완료 화면에서 '다시 신청하기'를 클릭했을 때 모든 입력칸과 상태가 초기화되고 1단계로 복귀함을 확인했습니다.
- **모바일 화면 조작**: 브라우저 폭을 768px 및 375px로 줄였을 때 단계별 박스 여백이 조절되고 버튼이 세로로 정렬되어 터치 조작이 편리함을 확인했습니다.

## 9. [9주차] 폼 UI와 입력 경험 설계

### 1. 이번 주 추가·수정한 기능
> 8주차에 완성한 다단계 식물 등록 및 알림 관리 화면에 **폼(Form) UI의 입력 경험과 제출 안전성**을 대폭 보완했습니다. 
> 식물 이름 입력 시 실시간 글자 수(`0/20자`)와 조건 충족 피드백을 제공하고, 체크박스 선택에 따라 영양제 공급 주기 라디오 옵션이 노출·활성화되는 **조건부 입력**을 구현했으며, 최종 제출을 `form`의 `submit` 이벤트로 통합하여 **저장 중 버튼 잠금(`저장하는 중…`)을 통한 중복 제출 방지** 및 **저장 실패 시뮬레이션(`?save-error=1`)과 입력값 보존 처리**를 완성했습니다.

### 2. 입력 항목 및 검증 조건
- **식물 이름 (애칭)**: 필수 입력(`required`), 2자 이상 20자 이하(`minlength="2" maxlength="20"`). 입력 중 실시간 글자 수와 유효성 상태(`.is-valid` / `.has-error`) 및 안내 문구 갱신.
- **마지막으로 물 준 날짜**: 필수 입력(`required`), 미선택 시 오류 문구 노출 및 초점 이동.
- **영양제 공급 알림 (조건부 입력)**: 체크박스(`#nutrition-option`) 체크 시에만 영양제 주기 라디오 옵션(`#nutrition-options`)이 화면에 표시되고 `disabled`가 해제됨. 체크 해제 시 화면에서 숨겨지고 제출 대상에서 제외(`disabled=true`).
- **식물 종류**: `select` 드롭다운에서 선택 (다육이/선인장 선택 시 과습 주의 문구 동적 표시).

### 3. 신규 폼 인터랙션 시나리오
| 사용자 행동 | 확인할 조건 | 성공 반응 (정상 경로) | 오류 / 실패 / 다른 분기 반응 | 다음 행동 |
| :--- | :--- | :--- | :--- | :--- |
| **식물 이름 입력 (키보드 타이핑)** | 실시간 입력 감지 | 글자 수 카운터(`length / 20자`) 실시간 갱신. 2자 이상 입력 시 초록색 테두리(`.is-valid`) 및 "입력 조건을 충족했습니다." 안내 문구 변경. | 2자 미만 시 기본 안내 문구 유지. 기존 오류 상태였을 경우 2자 이상 입력 즉시 오류 해제. | 물 준 날짜 선택으로 이동 |

### 4. 브라우저 동작 확인 순서
1. **빈 값 및 오류 검증 확인**: 1단계에서 이름을 입력하지 않고 다음을 누르면 오류 문구와 함께 이름 입력칸으로 포커스가 이동하며, 1글자만 입력해도 "2자 이상 입력해 주세요" 오류가 정확히 분기되는지 확인합니다.
2. **실시간 입력 피드백 확인**: 이름을 2글자 이상 입력하는 즉시 오류가 해제되고 초록색 테두리와 함께 "입력 조건을 충족했습니다" 문구로 실시간 갱신되는지 확인합니다.
3. **조건부 입력(영양제 알림) 확인**: '영양제 공급 알림도 함께 받을게요'를 체크했을 때 라디오 버튼 3개가 나타나고 탭 키로 선택 가능한지, 체크를 풀면 영역이 숨겨지고 `disabled` 처리되어 제출 데이터에서 빠지는지 확인합니다.
4. **정상 제출 및 중복 방지 확인**: 3단계에서 제출 버튼을 누르면 "저장하는 중…"으로 바뀌며 버튼이 비활성화되어 중복 클릭이 차단되고, 저장 완료 후 하단 알림 목록 카드에 영양제 설정값까지 정상 반영되는지 확인합니다.
5. **저장 실패 시뮬레이션 확인**: 주소창에 `index.html?save-error=1`을 붙여 테스트했을 때, 고의적인 저장 실패가 발생하며 기존에 입력한 값들이 날아가지 않고 유지된 상태에서 버튼이 다시 켜지는지 확인합니다.
6. **완전 초기화 확인**: 4단계에서 '다른 식물 등록하기'를 눌렀을 때 폼의 모든 입력값과 글자 수, 영양제 라디오, 오류 상태가 깨끗하게 초기화되고 첫 입력칸에 포커스가 놓이는지 확인합니다.
