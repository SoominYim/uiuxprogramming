# 초록달력

처음 식물을 키우는 자취생을 위한 물주기 알림 서비스입니다.

## UX 계획

- **사용자**: 처음 식물을 키우는 자취생
- **목적**: 식물 관리 방법과 물주기 시기를 이해한다.
- **핵심 행동**: 키우는 식물을 등록하고 물주기 알림을 이메일로 신청한다.
- **정보 순서**: 서비스 소개 → 주요 기능 → 이용 방법 → 소식 받기

## 2주차에서 바꾼 구조와 이유

- `h1 + p`로만 되어 있던 1주차 본문을 `header` 안으로 옮겼습니다. 서비스 이름과 소개 문장이 페이지의 다른 정보(소개, 기능, 이용 방법 등)와 구분되는 대표 영역임을 나타내기 위해서입니다.
- 서비스 소개, 주요 기능, 이용 방법, 소식 받기를 각각 `section#about`, `section#features`, `section#steps`, `section#subscribe`로 묶고 이 네 영역을 `main`으로 감쌌습니다. 사용자가 실제로 이용하는 핵심 콘텐츠와 머리말(`header`)·꼬리말(`footer`)의 역할을 분리하기 위해서입니다.
- 주요 기능 3개는 순서를 바꿔도 의미가 유지되므로 `ul`로, 이용 방법 3단계는 순서대로 따라야 하므로 `ol`로 작성했습니다.
- `header`에 `nav`를 추가하고 각 링크의 `href`를 해당 `section`의 `id`와 연결해 페이지 안에서 바로 이동할 수 있게 했습니다.
- 소식 받기 영역은 `label for="email"`과 `input id="email"`을 연결해 라벨을 눌러도 입력칸이 선택되도록 했습니다.
- 서비스 이미지는 아직 준비되지 않아 `img` 태그를 주석으로 남겨두었습니다. `assets/images/service.jpg`가 준비되면 주석을 해제할 예정입니다.

## AI 비교 기록

동일한 서비스 소개("초록달력")를 AI에게 그대로 생성시킨 결과와 직접 구현한 `index.html`을 비교했습니다.

**정보 계층**
- 직접 구현: `h1`(서비스 이름) 아래로 `h2`(서비스 소개/주요 기능/이용 방법/소식 받기)와 `h3`(각 섹션의 세부 주제)를 두어, 페이지 전체에서 제목 위계가 하나로 통일됩니다.
- AI 생성본: 기능 카드마다 `h2`를 반복하거나 강조 목적으로 `h1`을 여러 번 사용해, 페이지의 대표 제목이 무엇인지 문서 구조만으로는 알기 어려운 경우가 많았습니다.

**시맨틱 구조**
- 직접 구현: `header`·`nav`·`main`·`section#about/#features/#steps/#subscribe`·`footer`로 콘텐츠의 역할과 포함 관계를 태그 자체로 표현했습니다.
- AI 생성본: `<div class="header">`, `<div class="section">`처럼 의미는 클래스 이름에만 담고 실제 태그는 `div`를 반복 사용하는 경우가 있어, 브라우저나 스크린 리더가 문서의 역할 구조를 인식하지 못합니다.

**접근성**
- 직접 구현: `nav aria-label="주요 메뉴"`, `label for="email"` + `input id="email"` 연결, 이미지 의미를 설명하는 `alt` 텍스트를 갖췄습니다.
- AI 생성본: `input`에 `label` 없이 `placeholder`만 넣거나, `alt="image"`처럼 형식적인 대체 텍스트만 넣는 경우가 있어 스크린 리더 사용자가 입력 목적이나 이미지 의미를 파악하기 어렵습니다.

**배운 점**
AI가 생성한 코드는 화면상의 모양은 비슷해 보여도, 태그 선택과 속성 연결까지 신경 쓰지 않으면 접근성과 문서 구조에서 차이가 크게 벌어진다는 것을 확인했습니다. 이번 과제에서는 역할(태그)·순서(위계)·포함 관계(중첩)·행동(연결 속성)을 직접 설계했기 때문에 이 차이를 좁힐 수 있었습니다.

## 3주차 CSS 수정 기록

### 수정한 내용
기능 카드를 가로로 나란히 배치하기 위해 부모 요소인 `.feature-list`에 `display: flex`와 `gap: 20px`을 적용하고, 자식 요소인 `.feature-card`에 `flex: 1`과 패딩, 테두리, 배경색을 적용했습니다.

### 수정 이유
세 가지 핵심 기능(물주기 알림, 식물 도감, 성장 기록)이 동일한 위계의 정보 그룹임을 한눈에 비교할 수 있게 하고, 카드 간격과 크기를 균등하게 유지하여 정보 탐색 피로도를 낮추기 위해 수정했습니다.

| 바꾼 속성 | 화면 변화 | 사용자 이점 |
| --- | --- | --- |
| `display: flex` · `gap: 20px` | 세 기능 카드가 한 줄에 균등한 너비와 일정한 간격으로 배치됨 | 제공되는 핵심 기능을 한눈에 비교하고 탐색하기 쉬워짐 |
| `hover` · `focus` · `active` · `transition` | 버튼과 링크 조작 시 배경색 변경, 아웃라인 강조, 미세 이동 등 부드러운 피드백 제공 | 현재 조작 중인 요소와 입력 상태를 명확히 인지할 수 있음 |

## 4주차 반응형 수정 기록

### 확인한 문제
- 390px 및 768px 화면에서 내비게이션 메뉴와 구독 폼(이메일 입력창과 버튼)이 가로로 남아 내용이 좁아지고 버튼이 밀리는 현상이 발생했습니다.
- 소개 영역의 텍스트와 이미지가 좁은 화면에서도 가로로 배치되어 가독성이 떨어졌습니다.
- 기능 카드가 고정 flex 비율로 설정되어 화면 너비 변화에 유연하게 대응하기 어려웠습니다.

### 수정한 내용
- `index.html`의 `head`에 `viewport` 메타 태그를 적용해 모바일 화면 너비 기준 렌더링을 보장했습니다.
- 주요 레이아웃 컨테이너(`header`, `main`, `footer`) 및 이미지에 `width: 100%`, `max-width: 1100px`, `height: auto`를 적용하여 화면 밖으로 넘치지 않도록 조정했습니다.
- 내비게이션(`.site-nav`)에 `flex-wrap: wrap`을 추가하고, 기능 카드 목록(`.feature-list`)을 `CSS Grid`(`repeat(auto-fit, minmax(260px, 1fr))`)로 전환해 자동 열 계산이 이루어지도록 변경했습니다.
- `@media (max-width: 768px)` 미디어 쿼리를 추가하여:
  - 내비게이션 메뉴를 세로 1열(`flex-direction: column`)로 전환
  - 소개 영역(`about-layout`) 및 구독 폼(`subscribe-form`)을 세로 1열 배치로 전환
  - 기능 카드 목록을 1열(`grid-template-columns: 1fr`)로 고정
  - 모바일 해상도에 맞게 제목 폰트 크기(`h1`, `h2`) 및 섹션 패딩/여백 축소
  - 이메일 입력창과 버튼의 너비를 100%로 맞추고 버튼 터치 영역(`min-height: 48px`) 확보

### 달라진 점 (화면 너비별 결과)
- **1100px**: 콘텐츠가 중앙에 배치되고 기능 카드가 3열로 넉넉하게 표시됩니다.
- **769px**: 데스크톱 기준 레이아웃이 유지되며 콘텐츠가 화면에 맞춰 자연스럽게 정렬됩니다.
- **768px**: 미디어 쿼리가 적용되어 메뉴·소개 영역·기능 카드·구독 폼이 한 열로 전환됩니다.
- **390px**: 가장 좁은 모바일 화면에서도 가로 스크롤이나 요소 겹침, 잘림 없이 모든 텍스트를 읽고 폼을 편리하게 조작할 수 있습니다.
